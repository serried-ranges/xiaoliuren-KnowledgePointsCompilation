# 32 内容、来源与发布审计门禁

> 更新：2026-10-13。本文件规定发布前的结构审计、内容审计和人工来源/许可复核。自动扫描只提供提示，不替代逐项审读。

## 一、准入原则

| 类别 | 处理方式 |
|---|---|
| 古籍/馆藏材料 | 记录具体版次、卷页、馆藏来源及文件页许可状态；不把某一数字平台标记写成馆藏机构授权 |
| 当代作者作品 | 标清作者自述和页面范围；逐页核对转载声明及其覆盖对象 |
| 整本电子书/扫描/程序/数据 | 分对象核对权利人、许可、复制、改编、汇编及公开传播范围；无明确依据时不镜像 |
| 第三方转载与笔记 | 检查来源链和许可证；访问到文件不等于有再发布权 |
| 项目归纳 | 标记为研究者分析；不得拼合多个未核来源来复建原作的表格、案例库或规则手册 |

## 二、结构审计

运行《附录·审计工具/audit.js》，核对：

- 研究层文档、CSV、目录和当前索引是否一致；
- 两位编号重复、内部交叉引用和稳定编号是否有效；
- 来源编号是否重复/缺号；
- 书稿章节、附录、目录和合订本是否存在；
- 政治措辞扫描结果及人工复核；
- 文件数量及报告生成状态。

结构审计未解决的引用或目录错误须修正后重跑。报告需与当前提交同版。

## 三、内容审计

运行《附录·审计工具/content_audit.js》，扫描神通符咒、仙鬼巫、命理恐吓、改运化解、信仰供养和疾病干预词语。逐条人工检查命中语境：是否为历史引用、名称状态、研究对象或现实建议；确认无背书、操作指引、恐吓或替代专业服务的内容。

扫描命中数量不是通过/失败结论；报告只记录位置与类别，判断由审阅者完成。

## 四、来源与许可人工双审

自动脚本不验证许可，另外使用以下清单：

1. 每项主张有来源编号、原始 URL/版次、作者、日期与页码/段落。
2. 页面转载声明逐篇核验，并分别判断文字、图片、附件、整本书、合集、代码和数据。
3. “限时免费”“系统免费”“页面可访问”“第三方可下载”不得写成镜像许可。
4. 对外引用范围与研究目的相称；长篇、整表、歌诀、案例或数据库需明确许可。
5. 第一审阅者提出逐项结论；第二审阅者独立回到原件核对来源、版本、许可、引文和同步情况。
6. 撤回的内容从当前树和所有派生文件移除；不得从本地旧稿或 Git 旧版本回填。
7. 结果同步到公开材料状态表、研究索引、书稿、附录、合订本和 PDF。
