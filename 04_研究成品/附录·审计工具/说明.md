# 审计工具说明

> 本文件夹是知识包的**常设审计工具**：每次更新资料包后，运行一次即可自检（研究层＋书稿目录一并覆盖）。

## 使用方法

1. 需要电脑已安装 **Node.js**（任意较新版本）。
2. 在**本文件夹**打开命令行（终端），执行：

```
node audit.js
```

3. 控制台会输出检查摘要；同时在本文件夹生成《审计报告.md》（覆盖式）。

## 检查项

| # | 检查 | 说明 |
|---|---|---|
| 1 | 文件清单 | 列出全部 md / csv / 文件夹，统计数量 |
| 2 | 00 索引完整性 | 每个文件是否都在《00 总览》中登记 |
| 3 | 交叉引用 | 检查《NN》旧式编号是否存在，并校验《R-NN》《D-22A》《B-NN》等唯一编号是否能定位到文件 |
| 4 | 版本戳 | 各文件的"第N版"标记一览（防版本混乱） |
| 5 | 来源编号 | 《10 来源清单》编号是否连续、有无重复 |
| 6 | 实际计数 | md/csv/文件夹实际数量（核对 00/10 中的计数表述） |
| 7 | **政治合规扫描** | 涉台/涉港/涉澳表述须带"中国／地区／特别行政区／台北"等规范限定词（**一个中国原则**；02/03/05层与根目录说明一并纳入；01/02层原始件保留原貌、不做改写） |
| 8 | **书稿目录扫描** | 《06_小六壬通识/书稿》一并纳入：文件清单＋政治合规＋交叉引用＋合订本存在性（排除元文档《书稿审计记录》与派生文件《合订本》） |
| 9 | **编号重名提示** | 输出 04 层同一两位前缀对应多个文件的情况；唯一编号与旧编号映射见《00 总览与阅读指南》的“引用编号规则” |

## 内容门禁（content_audit.js）

- 运行：`node content_audit.js`；输出《内容审计报告.md》。
- 扫描六类敏感词（神通符咒／仙鬼巫／命理恐吓／改运化解／信仰供养／疾病干预），提示 C 级"研究对象"分布。
- 书稿目录（《06_小六壬通识/书稿》）**同步扫描**，报告单列一节；元文档《书稿审计记录》与派生文件《合订本》不参与扫描。
- 规则、分级（A/B/C/D）与降权注册表见文档《32 内容审计与采信门禁》。
- 流程建议：**更新内容 → 跑双审计（audit.js ＋ content_audit.js）→ 修问题 → 记录**。

## 维护备注

- 目录结构若有调整（例如新增子文件夹），脚本无需修改；书稿目录路径变更时只需同步脚本中的 `BOOK_DIR`／`BOOK` 常量；
- 书稿单章增改后，先运行书稿文件夹内的 `_工具_生成PDF.js`（自动重建合订本＋PDF），再跑双审计；
- 若知识包改名为其他文件夹，脚本会自动以**其所在文件夹的上一级**为根目录（无需改代码）；
- 建议流程：**更新内容 → 跑审计 → 修问题 → 记录到《00》迭代记录**。

## 扫描范围与 05/06 层

- 结构/内容双审计覆盖：**04 研究成品**（本层）与 **06 书稿目录**（`06_小六壬通识/书稿`）；政治合规另扫 05/06 层说明及 05 层公开材料状态表。
- **05 书籍整理层**（`05_书籍整理/`，第三方源书 PDF＋02 层提取副本，一本 PDF 一个同名文件夹）不做敏感词自动改写；公开资格须逐项查看《公开材料状态表》。该表是发布治理记录，不代表已经取得授权。05 层正文仍需在发布前按具体材料人工核对来源、公开依据与引用范围。

> 当前脚本的《NN》检查只确认编号存在，不判断重号前缀下的具体目标；重号提示和唯一编号映射帮助人工消歧。新表格引用请使用唯一编号或完整文件名。
