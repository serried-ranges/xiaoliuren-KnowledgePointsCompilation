# 第34章　内容、来源与发布门禁

> 本章说明项目如何区分来源事实、作者主张、研究推断和发布权限。自动扫描是提示，不替代来源核验和人工审阅。

## 34.1 证据类型

| 类型 | 可确认范围 | 发布处理 |
|---|---|---|
| 古籍原件或馆藏页面 | 指定版本、页面或馆藏记录 | 记版本、卷页和原始页面；单独核对数字影像使用条件 |
| 现代研究文章 | 作者及文章提出的观点 | 署名并注明为研究观点；不当作古籍原证 |
| 官方网页、工具说明或作者自述 | 发布页面内容及发布者自述 | 按对象和具体页面登记；不推断整本作品、代码或数据授权 |
| 第三方转载、课程/资源目录 | 页面或书目线索存在 | 不从可访问性推定来源真实性或复制许可 |
| 项目原创归纳 | 本项目形成的分析 | 明确标为研究判断；可回到依据并记录分歧 |

## 34.2 发布依据检查

发布每项材料前，分别核对作品/版本、权利人、原始来源、允许的对象、复制/改编/汇编范围、公开渠道、期限及署名条件。下列声明不能相互替代：

- 单篇文章允许注明转载，不等于整套教程、电子书或案例集可镜像。
- 免费领取或免费阅读，不等于获得第三方再发布权。
- 工具免费使用，不等于代码、界面素材或完整数据表可复制。
- 古籍原作可能已进入公有领域，不代表某一机构的数字影像或数据库元数据可任意复制。
- 没有明确依据时，公开稿保留题名、必要的来源链接和未核状态，不保留全文、扫描、实质性表格、案例集合或数据库。

## 34.3 结构审计

结构脚本检查：

1. 研究层文件是否被总览索引覆盖；
2. 内部交叉引用是否失效；
3. 来源编号是否重复、缺号；
4. 书稿目录与文件清单是否一致；
5. 来源和发布状态是否同步到书稿、审计记录及派生 PDF。

发现问题后先修正文件，再重跑脚本。报告必须对应准备提交的同一版本。

## 34.4 内容审计

内容扫描覆盖研究 Markdown、附录文本、书稿章节和 CSV。敏感词命中只表示需要人工看上下文，不自动定为通过或违规。人工复核检查：

- 是否把作者自述、研究观点或术数判断写成已证事实；
- 是否存在来源不明的操作步骤、长段引文、表格、口诀或案例；
- 是否有健康、法律、财务或恐吓性表达被写成现实建议；
- 章节、来源表和公开材料状态表的说法是否一致；
- 扫描报告是否列出命中位置和上下文，且人工结论有记录。

## 34.5 来源与内容双审阅

第一轮审阅者逐项核对来源、版本、主张、引文和使用范围；第二轮审阅者独立回到原始页面或文件，复查这些判断及书稿同步情况。若第二轮复核尚未完成，状态标为“待复核”，不写成双人审计通过。

## 本章要点

- 页面可访问、材料免费、题名相似，都不能替代发布依据核验。
- 结构审计检查项目关系和引用完整性；内容审计检查主张、来源、上下文和现实风险。
- 自动扫描命中不是审核结论；报告、人工判断和当前文件版本必须一致。
- 发布许可或第二轮复核未完成时，明确标记待办，不宣称已通过。
