# 《小六壬通识》PDF 生成方案（说明文档）

> 用途：把书稿合订本一键生成 PDF，并说明**方案原理、依赖、用法、排错与维护方式**，便于后续反复调用与执行。
> 位置：`05_整理书籍/01_小六壬通识/`｜版本：2026-10-05（第2版：目录页码＋页脚页码＋书签）。

## 一、产物

| 文件 | 说明 |
|---|---|
| `小六壬通识·合订本.pdf` | **最终 PDF**（A4、约 148 页）：①独立封面；②扉页总目录**逐章显示页码**；③每页页脚"第 X / Y 页"；④**PDF 书签目录**（阅读器侧边栏可跳章） |
| `小六壬通识·合订本.md` | 合并源文件（脚本自动重新生成，含章级锚点与目录跳转；**无需手改**） |
| `_工具_生成PDF.js` | 生成脚本（零 npm 依赖；需 Node ≥ 22） |
| `_工具_生成PDF.bat` | Windows 一键运行（双击即可） |
| `_工具_paged.polyfill.js` | **Paged.js v0.4.3**（MIT；本地附带）——负责浏览器内分页、目录页码与页脚页码 |

## 二、方案原理（四步流水线）

```
书稿各章 md ──(_工具_生成合订本.js)──▶ 合订本 md（注入 <a name="chNN" id="chNN"> 锚点、目录改文档内跳转）
      ──(生成脚本内置转换器：MD→HTML＋排版 CSS)──▶ 中间 HTML
      ──(Paged.js 在浏览器内分页：@page 页脚页码、目录 target-counter 页码)──▶ 分页版式
      ──(Edge CDP Page.printToPDF：generateDocumentOutline)──▶ 合订本 PDF（书签目录）
```

**为什么这样设计**：

- **不依赖 Pandoc/LaTeX/Word**——只用 Node.js ＋ Edge/Chrome ＋本地 Paged.js；
- **页码与书签全部自动**——目录页码由 Paged.js `target-counter()` 计算；页脚由 `@page @bottom-center` 输出；书签由 Edge CDP `generateDocumentOutline` 从标题生成；
- **零 npm 依赖**——脚本内置迷你 Markdown 转换器；排版库为本地文件（断网可用）；
- **单章增改即全量同步**——脚本每次运行都重建合订本再转 PDF；
- **有回退**——若 CDP 打印失败，自动回退基础打印（无页码/书签），保证总能出 PDF。

## 三、依赖

| 依赖 | 要求 | 备注 |
|---|---|---|
| Node.js | **≥ 22**（需内置 WebSocket；建议 24） | 本机 v24 已验证；Node 18/20 将自动回退基础打印 |
| 浏览器 | Microsoft Edge 或 Google Chrome | 自动查找常见安装路径 |
| 字体 | 系统自带中文字体 | 默认微软雅黑 |
| 排版库 | `_工具_paged.polyfill.js`（已附带，901KB，MIT） | 缺失时仍可出 PDF，但无页码 |

可选环境变量：`PDF_BROWSER=...`（指定浏览器）、`KEEP_HTML=1`（保留中间 HTML）。

## 四、使用方法

**方式一（推荐）**：双击 `_工具_生成PDF.bat`。
**方式二**：本文件夹执行 `node _工具_生成PDF.js`。
**方式三（仓库根目录）**：`node "05_整理书籍/01_小六壬通识/_工具_生成PDF.js"`。

预期输出：`✓ PDF 已生成：…（X MB，格式校验通过，含书签目录）`；Paged.js 排版约需 1—3 分钟（148 页）。

## 五、常见修改点

| 想改什么 | 改哪里（`_工具_生成PDF.js`） |
|---|---|
| 页脚位置/样式/文字 | `css` 中 `@page` 的 `@bottom-center`（如"第 X / Y 页"） |
| 目录页码样式（连接符） | `css` 中 `a[href^="#ch"]::after` 的 `content` |
| 字号/行距/页边距/纸张 | `css` 中 `@page`、`body` 规则 |
| 章起新页 / 表格 / 引用框 | `css` 中 `h1`、`table`、`blockquote` 规则 |
| 封面文字 | `html` 模板中的 `section.cover` |
| 书签名来源 | CDP 打印参数 `generateDocumentOutline`（默认从 h1/h2 生成） |

> 注意：合订本 md 是**自动生成**的；改内容请改单章文件，再运行本脚本。

## 六、排错

| 现象 | 处理 |
|---|---|
| 目录/页脚没有页码 | 检查 `_工具_paged.polyfill.js` 是否存在；查看日志"Paged.js 排版完成"一行 |
| 日志显示"Paged.js 未在时限内完成" | 属机器较慢；PDF 仍会生成（可能缺页码），重跑一次即可 |
| 提示回退到基础打印 | 检查 Node 版本（≥22）与 Edge 版本；回退版 PDF 无页码/书签 |
| 中文显示为方框 | 在 `css` 字体列表加入本机已有中文字体 |
| 想检查中间 HTML | 设 `KEEP_HTML=1` 再运行（HTML 在系统临时目录） |
| 生成中途失败 | 完全退出 Edge 后重试；或升级 Edge |

## 七、维护约定（与书稿/审计的关系）

1. **标准更新流程**：改单章 → 运行 `_工具_生成PDF.js`（自动重建合订本＋PDF）→ 跑双审计（`04_研究成品/附录·审计工具/`）；
2. PDF 与合订本 md 均为**派生文件**，双审计不重复扫描；《书稿审计记录》亦为元文档、不参与扫描；
3. Paged.js 为第三方库（MIT，v0.4.3），升级时替换本地文件并在本说明记录版本；
4. 换机器重新生成只需：Node ≥22 ＋ Edge/Chrome ＋ 本书稿文件夹（含本地 Paged.js）。
